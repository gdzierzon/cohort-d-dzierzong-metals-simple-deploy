Purpose of this file

Provision the hosting plan and the web app that runs the Flask API, and configure it to connect to the database created in database.tf.

This is the piece of infrastructure the API's own code (covered by a future tutorial) actually runs on top of. Terraform's job here stops at creating the empty, configured hosting environment — the application code itself gets deployed into it separately by the azure-webapps-python.yml GitHub Actions workflow.

The full file code sample

terraform/app_service.tfresource "azurerm_service_plan" "metals" {
  name                = "${local.prefix}-appservice-plan"
  resource_group_name = azurerm_resource_group.metals.name
  location            = azurerm_resource_group.metals.location
  os_type             = "Linux"
  sku_name            = "B1"
}

resource "azurerm_linux_web_app" "metals" {
  name                = "${local.prefix}-api"
  resource_group_name = azurerm_resource_group.metals.name
  location            = azurerm_service_plan.metals.location
  service_plan_id     = azurerm_service_plan.metals.id

  # Deployment authenticates through OIDC, not a publish profile.
  ftp_publish_basic_authentication_enabled       = false
  webdeploy_publish_basic_authentication_enabled = false

  site_config {
    always_on        = false
    app_command_line = "gunicorn --bind=0.0.0.0 --timeout 600 app:app"

    application_stack {
      python_version = "3.11"
    }
  }

  app_settings = {
    DB_HOST                        = azurerm_postgresql_flexible_server.metals.fqdn
    DB_NAME                        = azurerm_postgresql_flexible_server_database.metals.name
    DB_USER                        = local.db_user
    DB_PASSWORD                    = var.db_password
    DB_URL                         = "postgresql://${local.db_user}:${replace(urlencode(var.db_password), "+", "%20")}@${azurerm_postgresql_flexible_server.metals.fqdn}:5432/${local.db_name}?sslmode=require"
    SCM_DO_BUILD_DURING_DEPLOYMENT = "true"
    FLASK_DEBUG                    = "0"
  }
}

The App Service Plan azurerm_service_plan

What a service plan isthe hosting slot

An App Service Plan is the actual compute capacity — think of it as renting a slot of server hardware. The web app resource below doesn't include its own hardware; it gets deployed onto a plan. One plan can even host multiple web apps, though this project only puts one app on it.

os_type = "Linux"operating system

Runs Linux rather than Windows. Azure App Service supports both; Python apps on Azure typically run on Linux.

sku_name = "B1"pricing tier

The Basic tier, size 1 — enough compute for development and light traffic, at a lower cost than the Standard or Premium tiers meant for production workloads.

The web app resource azurerm_linux_web_app

service_plan_idattaching to its plan

service_plan_id = azurerm_service_plan.metals.id is the reference that actually places this app onto the plan created above — the same reference pattern used throughout this project to connect resources without hardcoding IDs.

ftp_publish_basic_authentication_enabled = false
webdeploy_publish_basic_authentication_enabled = falsesecurity

Azure Web Apps normally support deploying code over FTP or WebDeploy using a simple username/password (a “publish profile”). Both are turned off here, because this project's deployment instead authenticates using the OIDC identity built in github_oidc.tf — one less password-style credential that could leak.

Site config: how the app starts site_config

always_on = falsecost vs. responsiveness

When false, Azure can let the app go idle after a period of no traffic, and it takes a moment to wake back up on the next request. Turning this true keeps the app running (and billed) continuously; this project accepts the occasional cold start to save cost in a development environment.

app_command_linehow the app actually starts
app_command_line = "gunicorn --bind=0.0.0.0 --timeout 600 app:app"

The exact command Azure runs to start the application. gunicorn is a production-grade Python web server; --bind=0.0.0.0 listens on all network interfaces (required so Azure can route traffic to it), --timeout 600 allows up to 10 minutes for a single request before giving up, and app:app tells Gunicorn to run the Flask application object named app inside the Python module app.py.

application_stack { python_version = "3.11" }runtime

Tells Azure which managed language runtime to install and run the app under — Python 3.11.

App settings: passing in the database connection app_settings

app_settings becomes environment variables inside the running app — this is how the Flask API, without any hardcoded values of its own, learns how to reach the database that database.tf created.

DB_HOST, DB_NAME, DB_USER, DB_PASSWORDindividual pieces

Four separate values the app can read individually if it prefers to build its own connection: the database server's address (azurerm_postgresql_flexible_server.metals.fqdn), the database name, the admin username, and the password — each pulled from the same resources and variables used to create the database itself, so they can never drift out of sync with the real values.

DB_URLone ready-to-use connection string
DB_URL = "postgresql://${local.db_user}:${replace(urlencode(var.db_password), "+", "%20")}@${azurerm_postgresql_flexible_server.metals.fqdn}:5432/${local.db_name}?sslmode=require"

The same information as the four settings above, pre-assembled into one standard PostgreSQL connection URL, for code that prefers a single connection string. urlencode() escapes any characters in the password that would otherwise break the URL's structure (like @ or :); the surrounding replace() then swaps urlencode()'s + (its way of encoding a space) for %20, the encoding most PostgreSQL client libraries expect instead. ?sslmode=require at the end forces the connection to use encryption.

SCM_DO_BUILD_DURING_DEPLOYMENT = "true"deployment behavior

Tells Azure's deployment engine (Kudu) to run its normal Python build steps — installing requirements.txt dependencies — every time new code is deployed, rather than expecting a pre-built package.

FLASK_DEBUG = "0"production-style behavior

Disables Flask's debug mode. Debug mode is convenient locally (auto-reload, detailed error pages) but is a security risk if left on for anything reachable from the internet.

Key terms for beginners

App Service Plan
The compute capacity a web app runs on in Azure — its size and pricing tier. Distinct from the web app resource itself, which is the application configuration deployed onto that capacity.
Environment variable
A named value made available to a running program by its operating environment, rather than hardcoded in its source code. Terraform's app_settings map becomes these inside the web app.
Gunicorn
A widely-used production web server for Python applications, responsible for actually receiving HTTP requests and handing them to the Flask app.
URL encoding
Converting characters that have special meaning inside a URL (like @, :, or a space) into a safe escaped form, so the URL still parses correctly.
