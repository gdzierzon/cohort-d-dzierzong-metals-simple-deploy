What this project is start here

metals-simple-deploy is a small, complete application: a Python API backed by a PostgreSQL database, running in Azure. “Complete” means it isn't just application code — it also includes everything needed to actually stand up the cloud resources that code runs on, and to deploy changes to both safely and repeatably.

The three parts of this project overview

Each part has a narrow, distinct job. Skimming what each one is for here will make the deeper tutorials easier to follow, since Terraform's whole purpose is to build the infrastructure the other two parts run on.

Part 1

The API

A Python web application (built with Flask) that answers requests over the internet — for example, looking up or saving metals-pricing data. It contains the actual business logic of the app: what happens when someone calls a given endpoint.

PythonFlaskAzure App Service

Part 2

The Database

A PostgreSQL database that stores the application's data persistently. The API connects to it to read and write records, so the data survives even if the API itself restarts or redeploys.

PostgreSQLAzure Flexible Server

Part 3

Terraform

The infrastructure layer underneath the other two. Terraform creates the actual Azure resources — the resource group, the web app hosting the API, and the database server — and wires them together, before either piece of application code ever runs.

How the three parts fit together the big picture

The order above isn't arbitrary — it's roughly the order things have to happen in. Terraform runs first and builds the empty, configured Azure environment (the database server, the web app hosting slot, the security identities). Only once that environment exists does it make sense to deploy the API's code into it, or load starting data into the database. Change the infrastructure through Terraform, change the application through its own code — the two are deployed independently, but neither works without the other.
