This project has four moving parts that work together: a small web API, a database the API reads and writes, a browser-based UI that calls the API, and Terraform, the tool that creates the cloud infrastructure the API and database run on. What this project is start here

metals-simple-deploy is a small, complete application: a Python API backed by a PostgreSQL database, running in Azure. “Complete” means it isn't just application code — it also includes everything needed to actually stand up the cloud resources that code runs on, and to deploy changes to both safely and repeatably.

The four parts of this project overview

Each part has a narrow, distinct job. Skimming what each one is for here will make the deeper tutorials easier to follow, since Terraform's whole purpose is to build the infrastructure the API and database run on, and the UI's whole purpose is to be a browser window onto the API.

Part 1

The API

A Python web application (built with Flask) that answers requests over the internet — for example, looking up or saving metals-pricing data. It contains the actual business logic of the app: what happens when someone calls a given endpoint, and, now, who's allowed to call it.

Running the entire application in development quickstart

All three application pieces — database, API, and UI — run locally at the same time, each in its own terminal, each listening on its own port. Start them in this order; each step depends on the one before it. Every command below runs from the project root unless noted otherwise.

StepWhat it startsCommand
1One-time setup: Python dependencies and environment variablespip install -r requirements.txt, then copy .env.example to .env and fill in DB_* and JWT_SECRET_KEY
2Database, via Docker Composedocker compose up -d db
3API (Flask, defaults to port 5000)python metals_api/app.py
4UI (static file server, port 8888)cd metals_ui then python -m http.server 8888

Once all three are up, open http://localhost:8888 and log in with one of the seed accounts (admin or customer, password password for both — see the database tutorial). For the full detail behind each step — the schema and reset process, every endpoint and how authentication works, or how the UI decides what to show — see the Database, API, and UI tutorials.

How the four parts fit together the big picture

Terraform runs first and builds the empty, configured Azure environment (the database server, the web app hosting slot, the security identities). Only once that environment exists does it make sense to deploy the API's code into it, or load starting data into the database. The UI, by contrast, isn't deployed into that Azure environment at all in local development — it's a static folder that simply points at wherever the API is running, over an ordinary HTTP connection. Change the infrastructure through Terraform, change the application through its own code — each part is deployed independently, but none of them work without the ones underneath.

Deployment: two ways to build the infrastructure pick a path

Every Azure resource this project needs — the resource group, the database, the web app, the GitHub deployment identity — can be created two different ways. Both end up in the same place; they just get there differently, and reading both is one of the best ways to understand what Terraform is actually doing underneath its own syntax.

Option 1

Manual

Run individual Azure CLI commands by hand, one resource at a time, using the scripts in utility_scripts/. No preview, no state file — just the same az commands you'd type yourself, in a fixed order. The most direct way to see exactly what's happening in Azure.

Azure CLIPowerShellBash

Option 2

Automated (Terraform)

Describe the infrastructure you want as code, and let Terraform figure out how to get there — previewing every change first, remembering what it already built, and tearing everything down cleanly when you're done. The approach this project actually uses day to day.

TerraformAzureGitHub Actions

Pick manual or automated above and dig in — both tutorials are ready whenever you are.
