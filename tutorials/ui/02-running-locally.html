Running the UI with a Plain Static Server

metals_ui/ has no build step, no bundler, and no dependencies — it's plain HTML, CSS, and ES modules, so any static file server can host it. This project's convention is Python's built-in one. This page covers that one command, how the UI finds the API, and the order to start every piece of the stack in.

Serve command → python -m http.server 8888 Local UI address → http://localhost:8888 API base URL → set in runtime-config.js CORS → already open in metals_api/app.py

Purpose of this page

Get metals_ui/ on screen in a browser, talking to a real Metals API, without guessing at start order.

Before you start it prerequisites

  • Python 3 available on your PATH (only needed for http.server — any other static server, like npx serve, works exactly the same way).
  • The Metals API already running and reachable, since every catalog and admin page calls it directly — see the start order below if you haven't started it yet.

Serving the folder the one command

Run this from the project root.

terminalcd metals_ui
python -m http.server 8888

Open http://localhost:8888 in a browser. That loads index.html once; from there, every page you visit — #/elements, #/admin/coins, and so on — is just a change to the URL's hash, handled entirely by js/router.js in the browser. The server never sees those paths, so unlike some single-page apps, this one needs no route-rewrite configuration at all — a plain static file server is enough.

Pointing the UI at an API runtime-config.js

The UI's own port and the API's port are configured completely independently. One file, loaded by index.html before any application module, holds the only address the UI needs to know. 

metals_ui/runtime-config.jsglobalThis.METALS_ATLAS_CONFIG = {
  apiBaseUrl: "http://localhost:5000/api",
};

js/config.js reads globalThis.METALS_ATLAS_CONFIG.apiBaseUrl and falls back to http://localhost:5000/api if it isn't set — which is why local development works with this file untouched. To point the same metals_ui/ folder at a deployed API instead (Azure, a teammate's machine, …), this is the only line to change; nothing in js/ needs to be touched or rebuilt.

Why the browser allows this at all cross-origin requests

http://localhost:8888 and http://localhost:5000 are different origins as far as a browser is concerned, so without explicit permission the browser would block the UI's fetch() calls to the API. The API already grants that permission for every origin: 

metals_api/app.py@app.after_request
def allow_cross_origin_requests(response):
    response.headers["Access-Control-Allow-Origin"] = "*"
    response.headers["Access-Control-Allow-Headers"] = "Authorization, Content-Type"
    response.headers["Access-Control-Allow-Methods"] = "GET, POST, PUT, DELETE, OPTIONS"
    return response

Nothing needs to be configured for local development because of this — it's called out here so a CORS error in the browser console reads as a real signal (the API isn't running, or isn't the one runtime-config.js points to) rather than a missing setting to hunt for.

Start order for the whole stack database → API → UI

Each piece depends on the one before it, so starting them out of order just produces connection errors further down the chain. The full walkthrough, with every command, lives on the tutorials home page.

OrderWhat startsCommand
1Database (Docker Compose)docker compose up -d db
2Metals API (Flask, port 5000)python metals_api/app.py
3Metals UI (static server, port 8888)python -m http.server 8888 (from metals_ui/)

Common errors and how to fix them

What you seeLikely causeHow to fix it
Catalog pages stuck on “Loading…”, network error in the consoleThe API isn't running, or runtime-config.js points at the wrong address.Start the API (Metals API tutorial), and confirm apiBaseUrl matches where it's actually listening.
Redirected straight back to #/login after logging inNo token was stored, or GET /api/auth/me failed right after login.Check the Network tab for the login and /me requests; confirm the API's JWT_SECRET_KEY is set (see the database tutorial's .env notes).
Admin pages show 403 Forbidden even though you're logged in as an adminThe account doesn't actually carry the Admin role.Confirm the role from #/admin/users (as an existing admin), or use the seed admin account from the database tutorial.
Address already in use on port 8888Another process (maybe a previous http.server) is already bound to it.Stop that process, or serve on a different port: python -m http.server 8889.
